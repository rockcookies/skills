# 语义

本节只在 SKILL.md 第 6 步的条件成立时读取。每项独立：没有对应产物就跳过该项，继续其余项。

零互引、`reference/` 与 `references/` 并存、功能相邻却不相识——记入观察，不当成悬空。

## evals 评测链路

技能下存在 `evals/` 时做。

1. **路径链**：`evals.json` / eval README 指向的 `expected-findings`、fixture 目录、清理路径，按提取规则解析。SKILL.md 声明的可选维度（如 `--dims=`）与 evals 入参对照。
2. **ground truth**：以 `expected-findings.json`（或同等文件）为声称集，到 fixture 源码核对符号、路径、计数。
   - `evals/fixture` 文件数 ≤ 15：声称集每一条都核对。
   - 否则抽查至少 3 条、至多 5 条，并在审查意见的方法里写明「抽查」。
3. **文档互锁**：finder 是否可读 ground truth、输出目录等约定，SKILL.md 与 evals README 双向各说一遍的，两边字面一致。

完成：路径链每条有标记；GT 按阈值逐条或抽查完毕；互锁约定已对照或已声明无第二份文档。

## 规则编号衔接

SKILL.md 用 `Rule N`（或「规则 N」）预告内容已移入另一文件时：打开目标文件，核对其标题或首条规则就是所预告的那一条。断号、重号、预告了但文件不接 → 记问题。

完成：每处「移入 / 详见 Rule N」都对过目标标题，或集合内无此类预告。

## 孤立节点

清单里入度为 0、且不是该技能 `SKILL.md` 的文件。深读到能归类：

| 类 | 含义 |
|---|---|
| 评测设计 | fixture 里故意无入边，迫使文件级扫描；expected-findings 或 eval README 已写明，或 finding 正要求发现该文件 |
| 入口 / 资源 | `SYNC.json`、资产、脚本入口、人类 README |
| 死文件 | 无入边、也无评测或入口角色 |

评测设计而 GT 未记载意图 → 观察（记录性），建议补一句，不当成必须修的连通性缺陷。

完成：每个孤立节点都有类。

## see-also

同一集合内技能零互引时：看 description 与正文是否同域（同一产品、同一 API、互补职责）。同域且用户在一侧提问不会被导到另一侧 → 观察，建议在 description 或正文加一行 see-also。自包含是技能加载的常态。

完成：零互引要么标为孤岛（可接受），要么给出具体的一对技能与一句建议。
