# 中文写作补充规则

配合 `unslop` 与 `technical-writing` 一起加载，仅在输出语言为中文时生效。

## 编排

**完成标准：** `unslop` 与 `technical-writing` 的 SKILL.md 都已读入并按其执行；或已点名缺失并停止。

1. 输出语言不是中文 → 不用本文件，走 `unslop` + `technical-writing`。
2. 读取 `unslop` 与 `technical-writing` 的 SKILL.md，按各自文件执行。缺哪个就报告哪个，然后停止。不要假装模拟。
3. `unslop` 的内容层、语气层、填充词层规则（第 3、5、9–11、20、22–25 条）和 `technical-writing` 的 Diátaxis 分层判断对中文同样成立，直接沿用，本文件不重复。本文件只处理三类问题：会因语言不同而失效的规则（词表、指代消歧的判定方式）、中文完全没有对应机制的问题（全角/半角、人称选择），以及中文特有的歧义来源（长定语、并列层级）。

## 延伸 unslop 第 7 条：中文 AI 词表

unslop 给的词表是英文的，对中文无效，换成下表。判断标准和 unslop 第 27 条一样：这句话换个项目名还成立吗？不成立才留。

### 黑话

| 少用 | 换成 |
| --- | --- |
| 赋能 | 帮助、支持，或说清楚具体做了什么 |
| 抓手 | 入手点、方法 |
| 闭环 | 说清楚流程从哪到哪 |
| 沉淀 | 积累，或直接说存下了什么 |
| 拉齐、对齐 | 统一、达成一致 |
| 心智 | 认知、印象 |
| 颗粒度 | 粒度，或直接说单位是什么 |
| 增量、存量 | 新增的、已有的 |
| 打法 | 方法、方案 |
| 链路 | 流程，或写出具体步骤 |
| 生态 | 说清楚指的是哪些产品或团队 |
| 场景 | 多数情况下可删，或换成「情况」「用途」 |
| 复用 | 重复使用，或直接说「用同一份」 |

| 少用 | 换成 |
| --- | --- |

## 延伸 unslop 第 9–10 条：中文机械对偶

连续使用「不是 A，而是 B」「不仅 A，而且 B」「从 A 到 B，再到 C」「一方面……另一方面……」会产生模板感。表达逻辑关系，不要强行制造修辞结构。

## 延伸 unslop 第 20 / 22 / 23 条：中文开场、过渡与套话

**空洞开场**（除非确实承担信息功能）：在当今……、随着……不断发展……、值得注意的是……、首先，我们来看……、众所周知……、不难发现……、可以看到……、在这个背景下……

**无意义过渡词**（只有在逻辑关系确实需要时才用）：此外、同时、需要指出的是、值得一提的是、更重要的是、不可忽视的是、总的来说、综上所述

**虚假宏大叙事**（除非有具体事实支持）：标志着……、开启了……、奠定基础……、带来革命性变化……、重塑整个行业……、意义深远……、划时代……、前所未有……。优先写产品增加了哪些功能、指标提升了多少、哪些用户因此受益、哪些限制仍然存在。

**聊天套话**：删除「希望这有帮助」「当然！」「好问题！」「很好的观点」一类开场，直接进入正题。

## 延伸 unslop 第 26 条：中文抽象隐喻

同一批英文隐喻名词（substrate、vector、north star 等）翻成中文后仍是隐喻，一样要拆。「抓手」「链路」「土壤」「基石」这类词只在字面指实物时保留，当抽象比喻用时换成具体机制或名词。

## Z1 全角与半角

中文正文用全角标点：，。；：”“‘’（）——、
中文和紧邻的英文单词、阿拉伯数字之间加一个半角空格，例如「Windows 中」「Go 项目」「5 个节点」。标点前后不加空格。代码、URL、命令、文件名内部保持原样，不人为加空格。

## Z2 破折号与省略号

用全角破折号「——」，不用英文 em dash「—」，也不用双连字符「--」代替。省略号用「……」（六个点算一个符号），不用「...」。

## Z3 引号

正文默认用中文弯引号“”。同一篇文档不要混用「」或英文引号。

## Z4 顿号与并列层级

并列短词用顿号「、」，并列完整分句用逗号或句号。「A、B 和 C」如果实际是「A 和（B 和 C）」这种嵌套关系，要用「以及」或重新断句说清楚层级，不能全靠顿号堆在一起，避免层级不明的歧义。

## Z5 指代消歧

「这」「该」「它」「其」必须对应唯一一个名词。回指对象是整句话或整个做法时，重复写出那个名词，不用「这」单独指代一整段逻辑——中文的「这」比英文「this」更容易被滥用成万能指代词，比 Global English 那条规则更需要留意。

## Z6 长定语拆分

「的」字前的定语超过约 12–15 个字就拆句。「负责处理用户上传的包含多张图片的压缩包的接口」要拆成「接口处理用户上传的压缩包，压缩包里可以有多张图片」。判断标准同 unslop 第 28 条：读者要往回读才能断句，就该拆。

## Z7 被动态

中文「被」字句比英文被动更别扭，非必要不用。动作发出者已知就写主动句：「系统校验请求参数」，不写「请求参数会被系统校验」。只有发出者确实不重要或未知时才用「被」。

## Z8 人称与语域（按 Diátaxis 模式选）

- Reference：不用人称，客观陈述。「配置项通过 `config.yaml` 设置」。
- How-to：用「你」，直接给步骤。「如果需要修改超时时间，编辑 `timeout` 字段。」
- Tutorial：用「我们」，跟着教程一起做。「接下来，我们启动服务。」
- Explanation：允许第一人称观点。「我倾向于……」「这里我的判断是……」
- 官方产品文案：用「我们」代表团队，不在个人身份下虚构「我们」。

## Z9 数字与单位

数字与英文单位之间按 Z1 加空格：「5 GB」「10 ms」。同一篇文档内数字写法保持一致，不要「三个阶段」和「3 个阶段」混用。

## 不要做的事

不把本文件当 unslop 的替代——内容层、语气层判断仍归 unslop。也不要在英文输出时加载本文件。
