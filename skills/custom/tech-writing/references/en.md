# English Writing Specifics

Load this file when the output language for this task is English.

## Cutting AI-isms

**Drop empty openers**: "In today's fast-paced world...", "It's worth noting that...",
"Let's dive into...", "As we all know...", "It's important to understand that...",
"When it comes to..." — unless the sentence actually carries information.

**Drop filler transitions**: "Furthermore", "Moreover", "That said", "It's also worth
mentioning", "More importantly", "At the end of the day", "In conclusion", "Overall" —
use these only when the logical relationship genuinely needs marking.

**Avoid false grandeur**: "game-changing", "revolutionary", "a testament to",
"unlock the full potential of", "in the ever-evolving landscape of", "paradigm shift",
"unprecedented" — unless backed by specific facts. Prefer stating what actually changed,
by how much, for whom, and what limitations remain.

**Avoid mechanical parallelism**: overusing "It's not just X, it's Y", "Whether it's
A or B", "From X to Y", constant rule-of-three lists ("fast, flexible, and reliable"),
and em-dash-heavy asides all read as templated when they stack up sentence after sentence.
Use them for actual logical structure, not decoration.

**Don't over-correct into a formula**: don't force every paragraph to be a different
length, don't ban all triads, don't require an opinion in every paragraph, don't force
first- or second-person everywhere. The real thing to avoid is every piece having the
same rhythm and skeleton.

**Drop decorative and assistant tells**: no decorative emoji in headings or body; drop
"Hope this helps", "Of course!"; drop openers like "Great question!" / "Great point!" —
go straight to the content.

## Common AI-tell vocabulary

| Overused | Prefer instead |
| --- | --- |
| crucial / vital | important, or name the actual stake |
| delve into | look at, cover, discuss |
| ever-evolving | changing, growing |
| robust | describe the specific capability |
| seamless | describe the actual experience |
| leverage (as a verb) | use |
| comprehensive | say what it actually covers |
| significantly improved | give the actual before/after numbers |
| game-changing / groundbreaking | say what specifically changed |
| in today's [X] landscape | usually just delete |
| it's important to note | usually just delete, or state the fact directly |

## Avoid synonym-cycling

Don't mechanically rotate "challenge → hurdle → obstacle → difficulty → issue" just to
avoid repeating a word. If the meaning is the same, repeat "problem." Reasonable
repetition reads as natural, not lazy.

## Don't stack adjectives

Avoid "a powerful, efficient, flexible, modern, enterprise-grade solution." Instead:
"a Go service framework for enterprise use, with config management, task scheduling,
and a plugin system."

## Style mechanics

* Prefer contractions in article/opinion/tutorial voice ("it's", "you'll") when the
  tone is meant to be conversational; avoid them in formal docs/reports if the target
  audience expects a more formal register.
  Default to plain punctuation; don't use em dashes to chain three or more clauses in
  one sentence, and don't use one in every paragraph — that's a strong AI tell in English.
* Oxford comma: use consistently within a document.
* Headings should describe the content, not tease it ("Why we chose Ristretto", not
  "The answer might surprise you").
* One idea per paragraph; don't force uniform paragraph length.
* Use bullet lists for genuinely parallel items (steps, options, config keys), not as
  a way to avoid writing prose.
* Bold only what's genuinely load-bearing for a skimming reader, not every key phrase.
