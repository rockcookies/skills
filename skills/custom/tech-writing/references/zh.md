# 中文写作细则

本次输出为中文时加载本文件。

## 去 AI 味

**删除空洞的开场**：在当今……、随着……不断发展……、值得注意的是……、
首先，我们来看……、众所周知……、不难发现……、可以看到……、在这个背景下……
（除非确实承担信息功能）。

**删除无意义的过渡词**：此外、同时、需要指出的是、值得一提的是、更重要的是、
不可忽视的是、总的来说、综上所述——只有在逻辑关系确实需要时才使用。

**避免虚假宏大叙事**：标志着……、开启了……、奠定基础……、带来革命性变化……、
重塑整个行业……、意义深远……、划时代……、前所未有……，除非有具体事实支持。
优先写产品增加了哪些功能、指标提升了多少、哪些用户因此受益、哪些限制仍然存在。

**避免机械对偶**：连续使用「不是 A，而是 B」「不仅 A，而且 B」「从 A 到 B，
再到 C」「一方面……另一方面……」会产生明显的模板感。表达逻辑关系，而不是
强行制造修辞结构。

**不要机械执行反规则**：不要求每次只能列两项或四项，不要求刻意避免三段式，
不要求每段长短必须不同，不要求每段都加入个人观点。真正需要避免的是所有
文章都使用相同的结构、句式和节奏。

**删除装饰与协作套话**：标题与正文不加装饰性 emoji；删除「希望这有帮助」「当然！」；
删除「好问题！」「很好的观点」一类开场，直接进入正题。

## 高频 AI 词汇替换

| 尽量少用 | 优先考虑 |
| --- | --- |
| 至关重要 | 重要、关键 |
| 深入探讨 | 分析、讨论 |
| 不断演变 | 变化、发展 |
| 充满活力 | 活跃、增长 |
| 宝贵的 | 有用、实际 |
| 无缝 | 直接描述体验 |
| 强大 | 描述具体能力 |
| 卓越 | 给出数据或事实 |
| 全面的 | 说明覆盖范围 |
| 显著提升 | 给出具体变化 |
| 令人印象深刻 | 描述具体原因 |

## 避免同义词轮换

不要为了避免重复，机械替换「挑战 → 难题 → 困境 → 障碍 → 问题」。
如果语义相同，就直接重复"问题"。自然写作允许适度重复。

## 不堆砌形容词

避免「一个强大、高效、稳定、灵活、现代化的企业级解决方案」，改为
「这是一个面向企业场景的 Go 服务框架，提供配置管理、任务调度和插件机制。」

## 人称

技术文档优先「可以通过……」「配置文件中……」，必要时用「你可以……」。
技术文章可以用「如果你正在使用……」「我更推荐……」。
观点文章自然使用「我的判断是……」「我更倾向于……」。
官方文案使用「我们提供……」，但不要在非官方身份下虚构"我们"。

## Markdown 与排版

标题说明内容，不为了"有冲击力"而制造悬念（推荐「为什么选择 Ristretto」，
不推荐「终于找到正确答案了」）。

段落不机械要求"3～5 行"，真正的标准是一个段落只表达一个完整意图。

列表适合并列信息、配置项、条件、步骤、优缺点，不要为了排版把正常段落
全部改成列表。

粗体只强调真正重要的信息。

**标点**：默认使用中文全角标点。中英文混排时保留一个空格，例如
`Windows 中`、`Go 项目`、`5 个节点`、`API Gateway`。代码、URL、命令、
文件名不要人为加入空格。
