# trim：精简 Agent 上下文与 Skills

模型变强后，过去补偿弱点的规则会变成阻碍。每次模型升级、或觉得 Agent 变笨重时跑一遍。
看着臃肿的内容常常不是写多了，而是放错了位置。

两阶段：**阶段一只读出清单，用户确认前不改任何文件**；阶段二才动手。

## 阶段一：只读清单

1. **盘点加载量。** 跑 `inventory.py`，分开看：每轮加载（根 `AGENTS.md`/`CLAUDE.md`、全局规则、没写 `paths:` 的规则、每个 skill 的 description）、条件加载（有 `paths:` 的规则、嵌套 `AGENTS.md`）、按需加载（skill 正文、references）。脚本给字符数，不是 token；要报 token 就写明 tokenizer。
2. **逐段处理方式**：修 / 删 / 挪 / 改写 / 保留。挪的写清目的地，每条一句原因。做成一张表：

   | 位置 | 段落 | 动作 | 目的地 | 原因 | 加载 |
   |---|---|---|---|---|---|

3. **删除测试。** 逐句问：删掉后 Agent 的行为会变吗？「先读再改」「跑测试」「注意边界」这类本来就会做的删。拿不准的保留，标成待确认，不自行决定。
4. **写目标，不写路线。** 写清做完是什么样、怎么算完成、要什么证据。一个步骤删掉后换条路也能得到同样结果，就删；只有顺序本身是约束才留，如先验证再发布、先确认再删除。
5. **同一要求说三遍，换成一个词。** 术语要是 Agent 本来就懂的，首次出现配一行定义和一组 NO / OK。口号换成可识别的文风或检查项：
   - NO：「保持简洁，不要啰嗦，尽量精炼」
   - OK：「避免报告腔。NO：进行了相关方面的优化工作。OK：删除重复规则，留下两条实际约束。」
   - 「快、确定、开销小」可收成 `tight`，但必须写出可判断的标准，否则没法验收。
6. **放对位置。**

   | 内容 | 位置 |
   |---|---|
   | 提交、发布、回复、删除这类对话中随时触发的规则 | 根 `AGENTS.md` |
   | 跨项目硬约束 | 全局规则 |
   | 项目命令、发布步骤 | 项目 `AGENTS.md` / `docs/` |
   | 需要判断的流程 | skill |
   | 同样输入总是同样输出 | 脚本或 hook |
   | 「做 Y 之前先读 X」 | hook：做 Y 时注入 X |
   | 只有部分场景用到 | skill references 或 `docs/`，根目录留一句何时去读 |
   | 长期决策与理由 | `docs/adr/` |

7. **Skill 描述**只写做什么、何时用、不用于什么；近义词放 `when_to_use`；部分场景才用的内容放 references。判断 skill 有没有人用要看真实调用记录，只 grep 名字不算；没有记录就标 `usage unknown`，不据此删。要删的 skill 先列给用户。

## 不要删（整段原样保留）

- 用户偏好、被否掉的方案和原因、机器环境
- 不报错的坑；看着像出错其实正常的现象
- 描述句里「从不写入」「不上传」这类半句约束
- 删数据、花钱、发布、提权、改写已推送历史的规则
- 带日期的拍板决策记录

## 阶段二：确认后执行

1. **先搬后压。** 能整行搬进按需文件就整行搬，不边搬边改写；不可逆规则原样整段搬。搬完再合并重复、改写表达。
2. **搬法。**
   - 搬进 `docs/` 的内容，根目录留一句什么时候去读。
   - 根目录不建 `CLAUDE.md`（见 [hierarchy-model](hierarchy-model.md)）。
   - 项目里重复全局规则的句子，只有用户用的每个工具都读全局规则时才删。
3. **自检。** `audit.py` 查 `paths:` 的 glob 都能匹配真实文件；grep 拆走的旧文件名；`lost_lines.py` 列出全部消失行，每一行都要对上已确认的删除。
4. **独立复核。** 交给没参与精简的 Agent：只给消失行清单和仓库，不给你的理由和结论。让它搜关键名词，不搜整句；意思在哪都找不到的，原样恢复。
5. **验证真的会被加载。** 静态脚本只能证明 glob 与文件的关系。在移过去的文件里埋一个暗号（canary），开新会话：先读一个匹配的文件再问暗号，应答得出；再在另一个新会话读一个不匹配的文件再问，应答不出。验完删掉暗号。
6. **沉淀。** 用户要求时，把本次清单、被拍板保留的项和日期记进 `docs/` 下的一份记录；下次升级模型时按这份重跑，只复查上次标成待确认和 `usage unknown` 的项。
